# 嘟嘟哒：录制操作单

配音与剪辑由你完成。完整分镜和可直接朗读的旁白见 [五分钟稿](demo-video-runtime-validation-2026-09-05.md)。本页供录制时操作。

## 使用已登录的真实账号

打开 `http://127.0.0.1:5173`，确认嘟嘟哒 QQ 账号在线，然后选择录制用测试群。AstrBot 配置入口为 `http://127.0.0.1:6185`。

宣传海报位于 `docs/assets/dududa-poster.png`。浏览器建议 1920 × 1080、100% 缩放；录制时将群聊消息区滚动到当前讨论。

如果服务已经运行，直接使用。服务停止时从项目根目录执行 `bash manage.sh up`，在 NapCat 确认 QQ 登录状态，再执行 `bash manage.sh web-connect` 连接前端。

## 0—1：海报与 WebUI

1. 打开宣传海报，开场 15 秒，介绍「生活在 QQ 群里的 AI 群友」。
2. 进入 WebUI，选择「你的真实测试群」。
3. 展示联系人、消息区、Agent 对话、三档模型和配置页。
4. 使用下方任一已测问题完成一次 Agent 对话，再打开「运行」展示模型、耗时、能力与结果。

## 2：真实 QQ 账号下的四人入站模拟

使用已经登录的嘟嘟哒 QQ 账号，在真实前端 `http://127.0.0.1:5173` 选择测试群。四位模拟发言者为萌萌哒、九鸟、美香、DinaMist；完整的 20 条台词保存在 `tests/fixtures/recording/math-analysis-discussion.json`。

测试程序从该群读取实际成员，优先用群名片匹配姓名，经 AstrBot 的 OneBot 消息转换和正式主动参与流程处理。群历史查询在这次模拟中提供逐条累积的固定台词，模型与 iCourse 真实执行。加上 `--deliver` 后，正式回复通道会把嘟嘟哒的结果发到指定 QQ 群。

```bash
uv run --locked python ops/cli/rehearse_qq_group.py \
  --bot-id <嘟嘟哒QQ号> --group-id <测试群号> \
  --platform-id test --reset --deliver
```

`--reset` 将当前群设置为评课关闭、自适应许可开启、主动搭话开启，等到 20 条讨论才判断是否参与。模型档位沿用该群配置；当前测试群使用深度档（DeepSeek V4 Pro）和长回答，QQ Runtime 等待上限为 300 秒。

逐步检查：

1. 评课下拉菜单选择「自动启用」，初始状态为「本群关闭」。
2. 前 19 条保持安静，第 20 条出现查询请求。
3. 配置页出现「嘟嘟哒已启用」，启用记录显示读取 20 条。
4. 实际调用 `icourse.public-query.v2`，以 `数学分析(B1)` 为关键词，查询对应教师与点评。
5. 嘟嘟哒回复萌萌哒的细致讲解需求、九鸟的证明需求、美香的课业负担需求，以及 DinaMist 的候选筛选和后续排课核对需求。

这 20 条是注入接收端的模拟消息，不会由四位成员账号在 QQ 群中实际发出。录制真实群聊画面时，由成员按固定台词发言；本命令用于先验证自动启用与真实回复链路。报告默认写入项目旁的 `dududa-recording-state/reports/native-result.json`。

## 3：七项能力镜头

在测试群 1098932694 的配置中，将本段要展示的插件设为「锁定启用」，回答长度选为「长」。前四句可在 QQ 群里 @嘟嘟哒发送；后两条表情命令直接发到群里。每段保留「插件状态 → 输入 → 完成结果」，等上一项结束再发送下一项。

| 序号 | 固定输入 | 应出现的内容 | 实际调用 |
| --- | --- | --- | --- |
| 1 | 二课里搜索英语角活动，列出活动名称和活动时间。 | 英语角活动名称及活动时间。 | `ustc.young.activities.search.v1` |
| 2 | 查询2026秋季学期数学分析B1的开课记录，列出课程名和任课老师。 | 数学分析(B1)，18 个教学班及教师，学期为 2026 秋季。 | `ustc.academic.lessons.search.v1` |
| 3 | 查询2026级计算机科学与技术普通主修培养方案的总学分要求。 | 2026 级普通主修，164 学分。 | `ustc.curriculum.public-query.v1` |
| 4 | 查询最近三条校园通知，带标题、日期和来源链接。 | 三条通知的标题、日期及官网链接。 | `notifai.notices.search.v1` |

教务查询支持「数学分析B1」「数学分析(B1)」「数学分析（Ｂ１）」等写法，并保留 B1 与 A1、B3 的区分。上表结果来自 2026-09-06 测试，活动与通知随数据更新变化。

本轮用当前部署的 Runtime 执行四项真实 MCP 查询；娱乐三项运行已部署的插件并捕获输出，未向 QQ 群发送测试回复。逐项调用参数、完成状态和回答保存在项目旁的 `dududa-recording-state/reports/seven-current.json`。

## 独立查询复测

真实 QQ 入站复测使用上面的 `rehearse_qq_group.py`。独立模拟环境的查询复测仍可使用 `test_recording_answers.py`。

MCP 原子查询使用录制实例内的 Console：

```bash
recording_ip=$(docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' dududa-recording-astrbot)
uv run --locked python ops/cli/test_recording_capabilities.py --url "http://${recording_ip}:8090"
```

实测报告存放于 `../dududa-recording-state/reports/`。录制配置的快速档保留轻量推理，标准档和深度档直接组织查询结果，回答篇幅独立设置。模型措辞会变化，验收重点是调用正确能力、回应四人的需求、引用真实来源。
