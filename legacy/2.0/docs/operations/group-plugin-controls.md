# 按群控制插件

进入群聊 → Agent → 配置 → **插件与能力**，切换「本群开启 / 本群关闭」，
再点击底部「保存配置」。配置按 QQ 账号和群聊分别保存，不影响其他账号或群。
编辑草稿不会自动保存，也不会向群里发送测试消息。私聊中不可使用群开关。

开关沿用现有 Scope Policy，与 MCP 一样由当前会话管理。自动复读开启时使用
`auto`，命令插件使用 `on`；需要细分时仍可使用旁边的高级模式选择器。
会话总开关关闭时，已配置开启的群插件也不执行。

| 功能 | 群策略 ID | 额外限制 |
| --- | --- | --- |
| Emoji Kitchen 表情合成 | `emoji.kitchen` | 新安装默认群关闭；开启后可用 `/emoji 😀 😭` |
| 自动复读 | `social.reread.auto` | 仍遵守全局配置、触发阈值与概率 |
| Arc 曲目、谱面和绑定 | `arc.compat` | 仍遵守宿主群白名单；B50 是独立开关，本次保持停用 |
| Sub2API 查询 | `sub2api.auto_query` | 仍遵守敏感数据访问白名单与独占群限制 |
| 校车查询 | `ustc.shuttle.read` | 使用原有 Scope Policy 与 Runtime 权限 |

下方「Runtime 插件」管理的是宿主安装状态，不是各群权限。安装插件不等于在所有群开启；
未接入群策略的第三方插件不能仅靠页面上的安装状态获得群级控制能力。

Web 与 AstrBot 必须共用 `DUDUDA_AGENT_POLICY_PATH`。已配置此路径时，未知群、缺失或
损坏策略默认关闭；表情、复读、Arc 和 Sub2API 在入口及异步响应输出前检查当前群策略。
未使用 Dududa 控制面的独立安装保留原插件全局配置行为。

上线保留现有群策略及全局硬限制。Arc 仅为已有明确白名单群补齐缺失的 `arc.compat`，
不覆盖已有值；Emoji 不自动为任何群开启。此前依靠空白名单全群复读的行为不再绕过群策略。

验证只使用模拟事件和隔离浏览器；不会自动给真实群发送消息或恢复 B50 查分。
