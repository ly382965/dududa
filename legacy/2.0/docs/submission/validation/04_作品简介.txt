1 作品背景与解决的问题
嘟嘟哒面向QQ 群中的持续交流，将自然语言理解、群聊参与、校园查询和人格表达组织成
一套智能体系统。它以“生活在QQ 群里的AI 群友”为产品定位，首批服务于校园生活、教学
支持和群体协作。
群聊中的请求经常分散在多人发言里：有人提出问题，有人补充条件，有人临时更正；课程、
活动、通知和教务资料又来自不同网站。用户需要一个能够理解当前讨论、在适当时机参与、查
询资料并说明来源的入口。管理员则需要按群控制参与频率和服务范围，查看回答所使用的模
型、工具及运行结果。
作品围绕三个实际问题展开：从连续讨论中理解需求；将需求落到可用的校园服务；让群聊
参与有节奏、可配置、可解释。明确提及Bot 可发起任务；在目标群开启自动参与后，普通讨论
也能形成回应机会。

规则与模型协同。规则识别明确来源、平台信号和输入约束，模型提取意图与实体。结构化
语义经过校验，再由确定性策略选择回应、查询、澄清或静默；身份、权限和输出目标由程序维
护。
业务能力统一。课程、活动、通知等服务各自声明输入输出与Provider，Planner 把自然语言
条件绑定到有界业务查询。当前采用单步计划，MCP worker 使用独立解释器解决宿主与客户端
的依赖版本差异。
计算与表达分开。模型档位、推理强度和正文篇幅分别设置。人格影响语气与信息呈现，不
能改变工具事实、来源和用户指定的精确格式。

4 WebUI 工作台设计
WebUI 将真实QQ 会话与智能体管理放在同一工作区：桌面端并列显示账号栏、会话列表、
聊天窗和可折叠的Agent 面板；手机端通过单页切换保留当前会话。界面提供浅色和深色主题，
以明确的文字和状态色区分QQ 在线、Runtime 可用及配置生效情况。
页面区域
设计与使用方式
消息工作区
查看同群讨论、读取历史和搜索已缓存消息；账号与会话始终对应当前操
作。
Agent 三个页签
“对话”输入问题和阅读回答；“运行”检查实际模型、工具、上下文与耗
时；“配置”维护群行为与插件范围。
模型与工具管理
管理三档Key 池、MCP 连接和插件；分别显示保存结果及应用到Runtime
的状态。
连接与异常反馈
首屏先显示工作区，后台刷新目录；错误指出历史读取、账号登录或
Runtime 调用等具体环节，并提供重试。
浏览器以同源HTTP/SSE 连接Node.js 网关；网关负责QQ 同步，并从服务端取得近期历史，
交给AstrBot 中的既有Runtime 生成预览。预览可使用校园工具，结果留在Web 中供管理员检
查。该设计让管理员沿“阅读讨论—设置服务—检查回答”完成连续操作。配套《设计文档》设
有独立的“WebUI 设计”一章，详述布局、数据流、交互及实现依据。
5 创新点
嘟嘟哒以自适应为核心：围绕当前群聊情境，分别调整使用的插件、计算路由和参与方式，
并通过WebUI 展示选择过程、支持人工配置。
1. 自适应插件选择。结合讨论主题、多人参与、需求持续性与当前请求，在管理员授权的服务
集合中选择并启用匹配插件。例如，选课讨论形成明确需求后启用评课查询，记录启用原
因，将自然讨论连接到具体校园服务。
2. 任务驱动的自适应路由。根据意图、复杂度信号、置信度、可用模型和预算选择计算档位，
并独立配置推理强度与回答篇幅。简单交流与复杂分析可采用不同路由，实际选择随本轮
任务变化，并保留选择依据。
3. 自适应群聊参与与表达。结合提及、追问、持续讨论和群策略选择回复、查询、澄清或静默；
再按任务组织回答篇幅与人格表达，使参与方式适应当前情境，同时遵守配置的冷却和频
率限制。
4. WebUI 工作台设计。将真实QQ 会话与Agent 对话、运行、配置整合为连续操作；管理员按
群设置偏好、允许范围与锁定项，观察实际模型、插件、上下文和耗时，形成“配置—预览
—观察—调整”的自适应管理流程。
这些创新集中在可解释、可配置的情境适应机制：当前以语义感知、规则与策略组合实现，
在线学习另作为后续研究方向。

服务地址为https://api.deepseek.com，协议为OpenAI 兼容Chat Completions。调用链为
Runtime →AstrBotModelProviderAdapter →AstrBot Provider.text_chat →DeepSeek HTTP API。后
端传入提示词、模型、输出额度、thinking 与reasoning_effort，接收回答正文和token 用量。
2026 年9 月6 日录制查询配置保留快速档轻量推理，标准档和深度档使用thinking:disabled，
直接组织工具资料。以下为标准档录制模式的等价请求示意：
POST https://api.deepseek.com/chat/completions
Authorization: Bearer <DEPLOYMENT_API_KEY>
Content-Type: application/json
{
"model": "deepseek-v4-flash",
"messages": [
{"role": "system", "content": "<task instructions>"},
{"role": "user", "content": "<question and tool evidence>"}
],
"thinking": {"type": "disabled"},
"max_tokens": 8192
}
常规推理模式改为thinking enabled，并设置low/high/max 等reasoning_effort。真实API Key 在
部署端管理。校园工具由程序执行后将结果交给模型，当前主链不依赖模型原生Function Calling
自主执行工具。
字段依据：DeepSeek 官方Thinking Mode 文档，2026 年9 月6 日核对；项目实际参数以模
型适配器及运行配置为准。
7 实际使用示例
选课讨论：群内连续提出讲解风格、证明训练和课业负担等需求；条件满足且已有授权后，
系统启用评课能力，查询课程与教师评论，按不同需求组织建议并附链接。
