# 嘟嘟哒演示视频：分镜与配音稿

总长约 5 分钟。按「海报开场 → WebUI → 自适应插件 → 其他能力 → 设计」录制。旁白与屏幕操作分别录，查询完成后再切下一镜；正常等待可以剪短。

## 0. 海报开场｜0:00—0:15

**画面**：全屏展示 [宣传海报](../assets/dududa-poster.png)，停留在标题和角色区域，再拉到完整海报。

**配音**：

> 这是嘟嘟哒，一个生活在 QQ 群里的 AI 群友。她能接住聊天，帮忙解决问题，也有自己的表达习惯。我们希望 AI 能真正参与群里的日常，成为群里的自己人。

## 1. WebUI 功能展示｜0:15—1:00

**画面顺序**：

1. 打开工作台，选择录制用群，展示联系人、群聊消息和群信息。
2. 打开 Agent 对话，展示模型档位和回答长度。
3. 打开运行记录，展示一次回答所用的模型、能力、耗时与结果。
4. 打开当前群配置，展示主动搭话和插件开关。

**配音**：

> 群聊是她生活的地方，Web 工作台让整个过程看得见、调得动。在同一个界面里，我们可以查看消息、和 Agent 对话，也可以追踪一次回答调用了什么模型、用了什么能力。不同群可以有不同的参与频率、说话风格和插件配置；推理投入与回答篇幅也可以分别调整。

## 2. 自适应插件展示｜1:00—2:40

**起始画面**：选择「数学分析选课讨论」场景。评课社区显示「本群关闭」，勾选「允许嘟嘟哒自适应启用」；主动搭话开启。四位参与者为小林、小周、小陈、小许。

**配音一：交代场景**：

> 接下来是一段固定的四人群聊模拟。开始时，评课社区还处于关闭状态，嘟嘟哒开启了主动搭话，也获得了按话题启用这项查询能力的权限。四位群友正在讨论数学分析选课：有人希望讲解细致，有人重视证明，有人关注课业负担，也有人需要先处理时间冲突。

**操作**：播放固定的 20 条讨论。开头、中段各保留数条清晰可读的消息；第 17—20 条完整展示。最后一句不 @ 嘟嘟哒。

**第 20 条**：

> 能查查评课社区的数学分析评价吗？请按我们四个人的需求各给一条选课建议，并附上对应的评课链接。

**结果画面**：展示评课社区变成「嘟嘟哒已启用」，然后展示 iCourse 调用和最终建议。打开回答中的评课链接，保留教师、点评内容与对应学期等可核对信息。

**配音二：解释结果**：

> 讨论形成了明确的选课需求，嘟嘟哒主动启用了评课社区，并把上下文带进这次查询。回答需要分别照顾四个人的需求：评价能帮助理解授课体验，而本学期是否开课、时间是否冲突，要结合教务信息判断。我们可以看到评课能力的启用状态，也可以沿着来源链接核对依据。

## 3. 其他 MCP 与插件｜2:40—4:15

**操作方式**：切到手动演示场景，逐个开启当前要展示的能力，再输入对应固定问题。每个镜头保留「开关 → 问题 → 结果」；不在查询尚未完成时重复提交。

| 画面 | 固定输入 | 重点展示 |
| --- | --- | --- |
| 第二课堂 | 二课里搜索英语角活动，列出活动名称和活动时间。 | 活动名称、时间、来源。 |
| 教务 | 查询2026秋季学期数学分析的开课记录，列出课程名和任课教师。 | 课程名称、教师与开课学期。 |
| 培养方案 | 查询2026级计算机科学与技术普通主修培养方案的总学分要求。 | 2026 级普通主修、164 学分与方案版本。 |
| 校园通知 | 查询最近三条校园通知，带标题、日期和来源链接。 | 通知标题、日期和来源。 |
| 校车 | 列出工作日东校区到西校区上午的校车发车时刻。 | 路线和时刻表版本。 |
| Emoji Kitchen | `/emoji 😀 😭` | 合成表情图片。 |
| 自动复读 | 三位模拟群友依次发送「一起聊天，一起变好！」 | 达到设定阈值后的一次复读。 |
| Arc 曲目 | `/arc info Testify` | 曲目信息；谱面镜头使用 `/arc chart Sayonara Hatsukoi ftr`。 |
| 用量查询 | `/sub2api status` | 录制样例中的服务状态。 |

五个自然语言问题和 26 项 MCP 查询已逐项实测。操作入口、重置步骤与预期结果见 [录制操作单](recording-runbook.md)。查询前将本次回答长度选为「长」，录制时按清单顺序操作。

**配音**：

> 这些能力也可以手动开启。嘟嘟哒能查询第二课堂活动、教务安排、培养方案、校园通知和校车，把分散的信息入口变成群里的一句话。表情合成、复读和曲目查询，则让她也能参与轻松的互动。每项能力独立接入、独立配置，同一套系统可以继续扩展到科研、社团和其他群聊场景。

## 4. 介绍设计｜4:15—5:00

**画面**：展示设计文档中的架构图，依次突出 Context、Social Engine、模型路由、Capability/MCP、Persona、Memory；最后回到海报或 GitHub 首页。

**配音**：

> 这套体验由几层协作完成。上下文感知整理群里正在讨论什么；Social Engine 决定是否参与，以及是否需要启用查询能力；模型路由分配推理投入，Capability 和 MCP 执行具体任务；Persona 负责把结果组织成她自己的表达。我们也在继续接入长期记忆、群友印象、多 OC 与 Skill 编排，让每次互动都能成为下一次相处的基础。一起聊天，一起变好，让 AI 成为群里的自己人。

## 拍摄桌面准备

- 使用录制用群和四位固定模拟成员；关闭桌面通知，浏览器缩放设为 100%。
- 固定 1920 × 1080 画面，中文输入法与页面字体提前加载。
- 海报、WebUI、排练控制页和架构图分别放在四个标签页。
- 第二段重录前先重置场景，确认评课社区回到关闭状态。
- 第三段按固定问题逐项展示，保留结果完成状态和来源；配音后期单独录制。

录制入口：海报、WebUI、插件实测素材和架构图均已准备在本机录制工作台，具体地址见 [录制操作单](recording-runbook.md)。
