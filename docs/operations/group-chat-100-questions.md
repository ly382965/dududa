# 嘟嘟哒群聊测试问题表（100 题）

## 使用说明

- 默认在群聊中 `@嘟嘟哒` 后提问；标注“不 @机器人”的题除外。
- 标注“先发”的题按顺序发送；上下文关联题应在同一个群里连续测试。
- “通过标准”是验收目标，不代表功能均已实现。
- 第 21—40 题涉及群历史：整理本表时，当前链路仍存在历史传递缺口。没有上下文时，应明确说明，不能编造或显示空白成功。
- 第 93、94 题只在隔离测试环境模拟服务故障，不要为了测试中断生产服务。
- 权限与安全题不得使用真实密码、API Key、Cookie 或未授权的私聊内容。
- 自动搭话具有概率性；单次没有回复不代表失败，必须结合开关、冷却、限额和多次观察判断。
- 工具不可用或没有结果不一定判失败：如实说明原因、不伪造结果，也可以符合对应题目的通过标准。

## 判定注意事项

- HTTP 200、模型名和耗时不等于生成了有效回答；要检查正文、终态与原因。
- “明确说明无法完成”可以通过失败处理或真实性检查，但不能据此宣称对应业务能力已实现。
- Web 无发送预览通过，不等于真实 QQ 投递已经验收通过。
- 模型／挡位和工具调用数以实际运行记录为准，不根据题目难度或回复口吻猜测。
- 第 89 题在群聊中可以回复草稿；不得另行发布通知或群发。Web 预览则不应产生任何 QQ 发送。
- 发布测试报告前脱敏群成员身份、群号、原始聊天、凭据及私有链接。
